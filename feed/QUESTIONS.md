# Collector 확인 사항

- Q01. data/ 수정 금지와 data/catalog.json의 datasets 추가가 충돌합니다. 더 구체적인 최초 실행의 data/ 보존 지시를 적용하여 기존 파일은 수정하지 않습니다. feed/index.json을 직접 진입점으로 제공합니다.
- Q02. 본문 상세 분석 정정을 반영했습니다. 공개 재배포 권한이 확인되지 않은 원문은 상세 재서술과 짧은 인용으로 제공합니다. 인용 한도는 항목별이 아닌 동일 출처 전체로 합산합니다.
- Q03. 11절의 공통 url/pub/evidence 검사는 서로 다른 주간 숫자 표·일정·상태·팩 메타데이터 스키마와 충돌합니다. 각 스키마의 source_url/date/source/evidence 필드로 검사하며, 확인하지 못한 필드는 빈값으로 추정하지 않고 누락·부분 실패로 표시합니다.
- Q04. pub 현지 날짜만 있고 시각을 모를 때 KST 09:00 경계는 확정할 수 없습니다. 경계 날짜의 기사는 시각 확인 전에는 후보에서 보류합니다.
- Q05. 기존 텔레그램 게시기가 공개 checkout 전체 파일을 allowlist로 검사합니다. feed/ 추가 뒤 기존 작업과 충돌하지 않는 게시 통합 경로를 점검합니다. 기존 화면·data/·중지된 자동화는 변경하지 않습니다.
- Q06. 원문 팩의 30~80 발언/20~40 수치와 팟캐스트에 없는 수치가 충돌할 수 있습니다. 없는 수치는 만들지 않으며 확보 범위와 미충족 이유를 기록합니다.

- Q07. 현재 data/catalog.json은 개발 루트에 없고 sites-public/dist/data/catalog.json에서 생성됩니다. 한 줄을 직접 고쳐도 기존 exporter 실행 때 없어지므로 생성기 연동이 필요합니다. feed 밖 파일을 수정하지 말라는 범위와 충돌하여 패치 제안만 보관합니다.
- Q08. tools/telegram-pipeline.js의 syncPublic/verifyCommit은 기존 공개 manifest 밖의 feed 파일을 거부합니다. 안전한 공존에는 이 게시기 및 export allowlist의 좁은 연동 변경이 필요합니다. 이를 바꾸지 않고 feed를 원격 main에 올리면 기존 자동 갱신이 실패하므로 공개 게시 단계는 preflight에서 차단합니다. 로컬 수집과 검사는 계속합니다.
- Q09. 프라이빗 호스팅은 접근 제어이며 저작물 재배포 권한 확인을 대신하지 않습니다. 확인된 권한의 전문만 지원합니다. 현재 GitHub Pages 공개 범위는 변경하지 않습니다.
- Q10. 일간 직전 영업일은 토·일을 제외하는 것으로 해석했습니다. 한국 공휴일 제외 여부가 명시되지 않았으므로 별도 휴일 달력은 추정하지 않습니다.
- Q11. 초기 주간은 화요일 시험 시각부터 지난 7일을 사용합니다. 이후 월요일06:00 실행은 그 시각부터 지난7일을 사용합니다. ISO 주차는 실행일 기준입니다.
- Q12. 입력 스키마에 사건 ID가 없어 의미상 중복의 자동 판정이 불완전합니다. 수집 단계에서 사건을 대조하고 선택적 event_key를 남기며 URL은 자동 차단합니다. 서로 다른 날짜의 독립 진행을 제목 유사도만으로 합치지 않습니다.
- Q13. 전문 팩의 quote와 요금표 evidence, 원문 주소도 원문 표기입니다. 한자 검사는 설명문에 적용하고 evidence/quote/URL/실제 검색어에는 적용하지 않습니다.

- Q14. 원문 문장 여러 개를 항목·팩마다 반복하면 동일 출처의 합산 인용 한도와 충돌합니다. 실제 연속 구절·짧은 표 셀을 근거로 보존하고, 문장 밖 조건은 독립 재서술과 source_url·표 머리글로 연결합니다. 짧은 구절만으로 모든 문맥을 재검증할 수 없는 한계가 있으므로 근거 원문 링크를 유지합니다.
- Q15. 초기 trial의 기사기간은 2026-11-10 16:20에 끝났으나 중단 후 가격표·환율 확인은 11월 11일까지 이어졌습니다. 기사는 원래 기간을 보존하고, 가격 스냅샷은 각 checked/checked_kst와 환율 as_of_kst를 따로 기록합니다. 이를 11월 10일 16:20 당시 값이라고 표시하지 않습니다.
- Q16. 비상장·비분리 공시 기업은 별도 분기 콜을 공개하지 않기도 합니다. 공식 최근 발표일을 확인하지 못한 기업은 발표가 없었다고 단정하지 않고 IR 감사·재시도 목록에 남깁니다. 팟캐스트의 비공개 자막·전사 준비 중 표시는 전문 확보로 간주하지 않습니다.
- Q17. 최초 주간에는 지난주 직접 관측 파일이 없어 Epoch 변화율과 GPU·모델 요금의 전주 변화를 계산할 수 없습니다. 이번 주 확인값을 기준선으로 보존하며 changed/prev를 만들지 않습니다.
- Q18. AA 비용 지표는 토큰 단가와 다른 뜻일 수 있습니다. 모델 지수·입출력 토큰 가격·사업자별 경로·양자화 정밀도를 분리하고, 원문에 없는 속도·TTFT는 null로 둡니다. 국내 견적형 요금과 과거 행사가는 현행 공개 단가로 대체하지 않습니다.
- Q19. 연속 실패는 동일한 논리 실행 안의 재시도를 중복 계산하지 않습니다. 과거 실패보다 뒤에 확인한 성공을 보존하고, 소스 원주소 실패와 대체주소 성공을 각각 남깁니다. 다음 일간/주간 실행에는 새 run_id를 사용해야 합니다.
- Q20. 최초 구축은 일간·주간 조사를 병행했고 한도 대기 중단을 포함합니다. 전체 활성 작업 구간은 남아 있지만 일간/주간 각각의 완결 소요시간은 분리 계측되지 않았습니다. 후보 fragment의 duration_seconds는 담당 작업의 기록이며 전체 실행 시간으로 합산하지 않습니다. 이후 실행은 작업 시작·종료·대기 시간을 별도로 기록합니다.

- Q21. 실적발표 자료가 먼저 나왔고 콜이 아직 열리지 않았거나 콜 자체를 확인하지 못한 경우, 발언 notes를 만들지 않습니다. release_only=true, call_deep=false, transcript_url="", notes=[]로 일반 뉴스기간 안의 자료만 기록합니다. 실적 콜의 3영업일 예외를 발표자료에 임의 적용하지 않습니다. 이후 실제 콜이 확인되면 새 발언을 followup으로 구분합니다.

- Q22. 2026-11-11 사용자의 게시 지시로 Q01·Q05·Q07·Q08의 최소 연동 범위를 진행합니다. 기존 화면과 원본 data/는 보존하고, 생성된 공개 catalog에는 feed/index.json 항목만 추가합니다. Collector의 검증된 파일 목록만 기존 exporter에 연결하며 기존 데이터의 evidence 금지는 유지합니다. 정기 예약 활성화는 이번 게시 작업에 포함하지 않습니다.

- Q23. 이번 시험 파일에는 parts 분할이 없습니다. 향후 같은 날짜의 분할 묶음을 단일 파일로 축소하면 아직 보존 기간이 지나지 않은 이전 part는 안전하게 중단하는 현재 규칙에 걸립니다. 이전 index와 부모 parts가 실제 참조한 동일 날짜 part만 정리하도록 보완하기 전에는 이 축소 정정을 자동 게시하지 않습니다. 이번 최초 게시에는 해당하지 않으며 정기 예약은 계속 PAUSED입니다.

- Q24. Q23의 분할 수 감소는 이전 index와 부모 parts의 참조 및 날짜·기간·형식·revision을 함께 확인하는 정리 규칙으로 보완했습니다. 사용자 후속 승인으로 검증·공개 게시 후 기존 Collector 두 정기 예약만 활성화합니다. Q22의 예약 제외 범위는 이 두 예약에 대해서만 대체됩니다.
- Q25. 수집 시각이 지난 가격표는 실제 재조회 시각을 남깁니다. MEM의 오래된 웨이퍼 관측은 이번 일간 숫자 배열에 넣지 않고 실패 사유로 남깁니다. 시장별 GPU 요금에서 공공 전용·OS·약정·리전·GPU 모델을 유지하며 모델을 확인하지 못한 상품은 가격 행으로 추정하지 않습니다.
- Q26. 실적 콜 분리는 ID 접두사로 판정하지 않고 earnings_call·investor_day 및 기존 보고서의 실적 형식으로 판정합니다. 일반 인터뷰의 iv 접두사가 실적 페이지로 이동하지 않도록 검사합니다.

## Q27. 모델 발매일 필드 정정 (2026-11-11)

기존 AA 자료의 released 50행에 발매월 뒤의 페이지 텍스트가 잘못 붙어 있었습니다. 원본 작업 기록은 보존하고 공개 값은 원문에 확인된 YYYY-MM만 남겼습니다. 날짜를 추정하지 않으며, 앞으로는 YYYY-MM-DD·YYYY-MM 또는 미확인 빈 값만 자동 검사를 통과합니다.

- Q28. 2026-11-11 일간 점검에서 Oracle Cloud Infrastructure RSS와 HPCwire RSS가 논리 실행 기준 연속 3회 실패했습니다. 정상 공개 웹에서 https://blogs.oracle.com/cloud-infrastructure/ 와 https://www.hpcwire.com/ 목록이 열려 대체 경로로 확인했습니다. RSS 실패 기록을 지우지 않고 목록·개별 원문 접근 상태를 별도로 보존합니다.

- Q29. 네덜란드 AMS2 인수의 최초 보도는 네덜란드어였습니다. lang 허용값이 ko·en·zh·ja뿐이라 이번에는 원문 언어를 다른 언어로 표시하지 않고 보류했습니다. 유럽 원보도 수집을 위해 ISO 언어 코드 허용 범위를 넓힐지 검토가 필요합니다.
